ปรับปรุง agent governance ของโครงการ LCBP3 ให้รองรับ multi-agent development โดยใช้กติกากลางชุดเดียวสำหรับ Devin, Agy, Claude, Codex และ local LLM/Ollama


เป้าหมายหลัก:
เปลี่ยนแนวคิดจาก agent-specific execution rules ไปเป็น **Universal / LCBP3 Agent Execution Contract** ที่ agent ทุกตัวต้องปฏิบัติตาม โดยให้ configuration เฉพาะของแต่ละ agent เป็นเพียง adapter บาง ๆ ที่อ้างกลับมายังกฎกลาง หลีกเลี่ยงการทำสำเนา policy ซ้ำหลายที่เพื่อลด configuration drift

ก่อนแก้ไข:

1. อ่าน `AGENTS.md` ทั้งไฟล์
2. อ่าน `.agents/rules/*` ที่เกี่ยวข้องทั้งหมด
3. ตรวจ configuration/instructions ที่เกี่ยวข้องกับ Devin, Agy, Claude, Codex และ Ollama ที่มีอยู่ใน repo
4. อ่าน ADR/spec ที่เกี่ยวข้อง โดยเฉพาะ:

   * ADR-041 สำหรับ current infrastructure / server placement
   * ADR-044 สำหรับ database schema / migration policy
   * ADR-009 เพื่อเข้าใจ relationship กับ ADR-044
5. ระบุข้อความที่ stale, contradictory หรือ duplicated ก่อนลงมือแก้
6. ห้าม infer architecture จากความจำ ให้ยึด accepted/implemented ADR และ repo ปัจจุบันเป็นหลัก

ให้ดำเนินการดังนี้:

## 1. ปรับ AGENTS.md ให้เป็น governance entrypoint กลาง

ทำให้ `AGENTS.md` เป็น policy/router สำหรับ AI agents ทุกตัว ไม่ผูกกับ vendor ใด vendor หนึ่ง

เพิ่ม section ชื่อประมาณ:

`LCBP3 Agent Execution Contract`

หรือชื่อที่สื่อความหมายเทียบเท่า

Contract ต้องระบุอย่างน้อย:

### Source of Truth Precedence

เมื่อข้อมูลขัดแย้งกัน ให้ใช้ลำดับดังนี้:

1. Accepted / Implemented ADRs
2. ADR amendments / superseding ADRs
3. Engineering Guidelines
4. Feature Specs / Requirements
5. Database schema / API contracts
6. Existing implementation

ห้ามแก้ conflict ด้วย assumption

ต้องระบุชัดว่า:

* ADR-044 เป็น canonical decision สำหรับ database schema/migration policy
* ADR-044 supersedes หรือ amends ส่วนที่เกี่ยวข้องของ ADR-009
* ADR-041 เป็น canonical decision สำหรับ current infrastructure/server placement

## 2. Repository Safety Contract

Agent ทุกตัว MUST NOT:

* push ตรงเข้า `main`
* merge PR โดยไม่มี explicit authorization
* deploy production โดยไม่มี explicit authorization
* ทำ destructive database/storage operations โดยไม่ได้รับอนุญาต
* bypass security/release gates
* invent table, column, API, infrastructure หรือ configuration ที่ไม่ได้ verify
* claim ว่า test/lint/typecheck ผ่าน หากไม่ได้ execute จริง

รักษากฎเดิมที่เข้มกว่าไว้ หากมีอยู่แล้ว

## 3. Database Contract

ทำให้ database policy สอดคล้องกับ ADR-044

* ห้ามสร้าง TypeORM migration files
* schema changes ให้ใช้วิธีที่ ADR-044 กำหนด เช่น schema SQL / delta SQL
* ก่อน generate query หรือ schema change ต้อง inspect schema/contract ที่เกี่ยวข้อง
* ห้ามแก้ database strategy จาก assumption

## 4. AI / Ollama Boundary

รักษาและทำให้ security boundary ชัดเจนว่า AI agents และ Ollama ไม่มี authority ในการเขียน production DB/storage โดยตรง เว้นแต่ architecture/ADR ระบุ explicit approved path

หาก agent ไม่มี filesystem, shell, SSH หรือ execution capability:

* ยังต้องเคารพ contract เดียวกัน
* ต้องรายงาน verification ที่ไม่ได้ execute อย่างตรงไปตรงมา
* ห้าม assume ว่า verification ผ่าน

ตัวอย่าง expected reporting:

* lint: NOT EXECUTED — shell unavailable
* typecheck: NOT EXECUTED — shell unavailable
* tests: NOT EXECUTED — execution tool unavailable

## 5. Change Discipline

ก่อนแก้ code หรือ config:

* identify applicable ADR/spec/rules
* inspect affected implementation
* ประเมิน regression impact
* ห้ามทำ unrelated refactor
* ห้ามเปลี่ยน public API / schema / infrastructure โดยไม่จำเป็นหรือไม่ได้รับ explicit instruction

## 6. Verification Contract

ก่อนถือว่างาน implementation เสร็จ ให้ run verification ที่ environment รองรับ เช่น:

* lint
* typecheck
* unit tests
* integration tests
* targeted E2E tests

ใช้ wording ประมาณ:

`Run all applicable verification supported by the current environment.`

หาก step ใด run ไม่ได้ ให้ระบุเหตุผล

ห้าม report success โดยไม่มี command/result รองรับ

## 7. Completion Report

ทุก implementation task ควรรายงานอย่างน้อย:

* files changed
* ADR/specs/rules consulted
* commands/tests executed
* verification results
* architectural impact
* known risks
* unresolved issues/ambiguities
* recommended follow-up

## 8. Agent-specific adapters

ตรวจ configuration/instruction ของ:

* Devin
* Agy
* Claude
* Codex
* Ollama/local LLM

เป้าหมายคือไม่ให้มีสำเนา governance policy เต็มชุดในแต่ละระบบ

แต่ละ agent-specific file ควรเหลือเฉพาะ:

* วิธี load/read `AGENTS.md`
* วิธี load relevant `.agents/rules/*`
* capability/tool-specific instructions
* limitations เฉพาะ agent
* vendor-specific workflow เท่าที่จำเป็น

หากพบ policy ที่ duplicate จาก `AGENTS.md`:

* ลด duplication โดยอ้างกลับไปยัง canonical policy กลาง
* แต่ห้ามลบ instruction ที่ platform นั้นจำเป็นต้องมีเพื่อให้มันอ่านกฎกลางได้จริง

ใช้แนวคิด:

`One governance contract, multiple thin agent adapters.`

## 9. แก้ stale / contradictory information

ตรวจและแก้ inconsistency ที่มีอยู่ โดยเฉพาะ:

* Ollama/current server placement ให้ตรง ADR-041
* database migration wording ให้ตรง ADR-044
* ADR-009 references ต้องไม่ทำให้ agent เข้าใจผิดว่า TypeORM migrations ยังเป็น policy ปัจจุบัน
* version / last synced metadata ใน `AGENTS.md` หากไม่ตรงกับประวัติจริง
* duplicated rules ที่มีโอกาส drift

อย่าแก้ข้อความเพียงเพราะ style ต่างกัน หากไม่มีผลต่อ correctness/governance

## 10. Scope Control

ห้าม:

* refactor application code ที่ไม่เกี่ยวข้อง
* เปลี่ยน architecture
* แก้ ADR ที่ accepted แล้ว เว้นแต่จำเป็นต่อ reference/cross-link และไม่มีการเปลี่ยน decision
* deploy
* merge
* push `main`
* ทำ destructive operation

ให้แก้เฉพาะ documentation/config/instruction files ที่จำเป็นสำหรับ agent governance

ก่อนลงมือแก้ไฟล์ ให้สรุปสั้น ๆ ว่า:

* conflicts/stale rules ที่พบ
* files ที่คาดว่าจะต้องแก้
* policy decisions ที่จะ preserve

จากนั้นดำเนินการแก้ได้เลย ไม่ต้องหยุดรอ approval เว้นแต่พบ ambiguity ที่อาจเปลี่ยน:

* architecture
* security boundary
* database policy
* production behavior

หลังแก้เสร็จ:

1. ตรวจ `git diff`
2. ตรวจ consistency ด้วย search ใน repo สำหรับข้อความสำคัญ เช่น:

   * `TypeORM migration`
   * `ADR-009`
   * `ADR-044`
   * `ADR-041`
   * `Admin Desktop`
   * `Ollama`
   * `push to main`
   * `production`
3. ตรวจว่า agent-specific files ไม่ขัดกับ AGENTS.md
4. run markdown/lint/check ที่ repo รองรับ ถ้ามี
5. ห้าม commit หรือ push เว้นแต่ได้รับคำสั่งเพิ่มเติม

Final report ต้องสรุป:

* Files changed
* Main governance changes
* Stale/conflicting rules resolved
* Agent adapters changed
* ADR/specs consulted
* Verification/search commands run
* Remaining ambiguities
* Risks
* Suggested next step

เป้าหมายสุดท้าย:

`AGENTS.md` และ `.agents/rules/` ต้องเป็น canonical governance ของ LCBP3 สำหรับ AI agents ทุกตัว

Devin, Agy, Claude, Codex และ Ollama ต้องสามารถทำงานภายใต้ execution contract เดียวกันได้ แม้ capability ของแต่ละ agent จะแตกต่างกัน

หลักการสุดท้ายคือ:

**Agent เปลี่ยนได้ แต่ project governance ต้องไม่เปลี่ยนตาม agent.**
